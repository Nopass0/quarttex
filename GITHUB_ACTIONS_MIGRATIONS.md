# GitHub Actions для автоматического исправления миграций

## Обзор

GitHub Actions настроены для автоматического исправления ошибок миграций при деплое. Система обеспечивает безопасный деплой без потери данных.

## Workflow файлы

### 1. `deploy.yml` - Основной деплой
**Триггеры:**
- Push в ветку `main`
- Ручной запуск (`workflow_dispatch`)

**Что делает:**
- ✅ Тестирует backend и frontend
- ✅ Копирует код на сервер
- ✅ Проверяет и исправляет SSL сертификаты
- ✅ Запускает миграции с автоматическим исправлением
- ✅ Проверяет состояние всех сервисов

### 2. `test-migrations.yml` - Тестирование миграций
**Триггеры:**
- Pull Request в ветку `main`
- Ручной запуск (`workflow_dispatch`)

**Что делает:**
- ✅ Тестирует безопасность миграций
- ✅ Проверяет скрипт автоматического исправления
- ✅ Тестирует применение миграций
- ✅ Проверяет схему базы данных
- ✅ Тестирует Prisma Client

### 3. `fix-migrations.yml` - Быстрое исправление
**Триггеры:**
- Только ручной запуск (`workflow_dispatch`)

**Что делает:**
- ✅ Запускает исправление миграций на продакшене
- ✅ Создает недостающие таблицы
- ✅ Применяет миграции
- ✅ Перезапускает backend
- ✅ Проверяет здоровье сервисов

### 4. `monitor-migrations.yml` - Мониторинг
**Триггеры:**
- Каждые 6 часов (cron)
- Ручной запуск (`workflow_dispatch`)

**Что делает:**
- ✅ Проверяет статус миграций
- ✅ Тестирует подключение к БД
- ✅ Проверяет существование таблиц
- ✅ Проверяет здоровье сервисов
- ✅ Отправляет уведомления при ошибках

## Автоматическое исправление

### При деплое

1. **Проверка SSL сертификатов:**
   ```bash
   bash ssl/ensure-fullchain.sh
   ```

2. **Применение миграций с исправлением:**
   ```bash
   # Попытка обычных миграций
   if bunx prisma migrate deploy; then
     echo "✅ Migrations applied successfully"
   else
     echo "⚠️ Migration failed, running auto-fix..."
     bash scripts/auto-fix-migrations.sh
   fi
   ```

3. **Создание недостающих таблиц:**
   - `Merchant` - таблица мерчантов
   - `Method` - таблица методов платежей
   - `User` - таблица пользователей
   - `Aggregator` - таблица агрегаторов

### При ошибках

Система автоматически:
- ✅ Создает недостающие таблицы
- ✅ Применяет миграции повторно
- ✅ Не удаляет существующие данные
- ✅ Продолжает деплой даже при ошибках

## Использование

### Автоматический деплой

```bash
# Просто запушите код в main ветку
git push origin main
```

### Ручной деплой

1. Перейдите в GitHub Actions
2. Выберите "Deploy to Production"
3. Нажмите "Run workflow"

### Быстрое исправление миграций

1. Перейдите в GitHub Actions
2. Выберите "Fix Production Migrations"
3. Выберите окружение (production/staging)
4. Нажмите "Run workflow"

### Мониторинг

Система автоматически проверяет состояние каждые 6 часов. При ошибках отправляет уведомления в Slack.

## Логирование

### Просмотр логов

1. Перейдите в GitHub Actions
2. Выберите нужный workflow
3. Нажмите на job
4. Разверните нужный step

### Ключевые логи

- `✅ Migrations applied successfully` - миграции применены успешно
- `⚠️ Migration failed, running auto-fix...` - запуск автоматического исправления
- `✅ Auto-fix completed` - исправление завершено
- `❌ Migration failed` - критическая ошибка

## Устранение неполадок

### Ошибка P3018

1. Запустите "Fix Production Migrations"
2. Проверьте логи в GitHub Actions
3. При необходимости запустите полный деплой

### Проблемы с SSL

1. Убедитесь, что `certificate.crt` существует на сервере
2. Проверьте права доступа к SSL файлам
3. Запустите `bash ssl/ensure-fullchain.sh` вручную

### Проблемы с Docker

1. Проверьте, что Docker запущен на сервере
2. Убедитесь, что пользователь имеет права на Docker
3. Проверьте доступное место на диске
