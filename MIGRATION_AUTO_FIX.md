# Автоматическое исправление ошибок миграций

## Обзор

Система автоматического исправления ошибок миграций обеспечивает безопасный деплой без потери данных. При возникновении ошибок миграций система автоматически создает недостающие таблицы и применяет миграции.

## Проблема

При деплое могут возникать ошибки типа:
- `P3018: A migration failed to apply`
- `ERROR: relation "Merchant" does not exist`
- `Database error code: 42P01`

## Решение

### 1. Автоматическое исправление при деплое

Система автоматически исправляет ошибки при выполнении `prisma migrate deploy`:

```bash
# Обычный деплой (теперь с автоматическим исправлением)
bash deploy.sh

# Безопасный деплой (рекомендуется)
bash safe-deploy.sh
```

### 2. Быстрое исправление на работающем сервере

Если ошибка возникла на уже работающем сервере:

```bash
# Быстрое исправление без остановки сервисов
bash fix-migrations-now.sh
```

### 3. Ручное исправление

Если автоматическое исправление не помогло:

```bash
# Запуск скрипта исправления вручную
cd backend
bash scripts/auto-fix-migrations.sh
```

## Как это работает

### 1. Обнаружение ошибки

При выполнении `prisma migrate deploy` система:
1. Пытается применить миграции
2. При ошибке запускает автоматическое исправление
3. Создает недостающие таблицы
4. Повторно применяет миграции

### 2. Создание недостающих таблиц

Система автоматически создает:
- `Merchant` - таблица мерчантов
- `Method` - таблица методов платежей
- `User` - таблица пользователей
- `Aggregator` - таблица агрегаторов

### 3. Безопасность

- ✅ **НЕ удаляет данные** - только создает таблицы
- ✅ **НЕ останавливает сервисы** - работает в фоне
- ✅ **Создает бэкапы** - перед критическими операциями
- ✅ **Проверяет существование** - не пересоздает существующие таблицы

## Скрипты

### `auto-fix-migrations.sh`
Основной скрипт автоматического исправления:
- Создает недостающие таблицы
- Применяет миграции безопасно
- Обрабатывает ошибки gracefully

### `safe-deploy.sh`
Безопасный деплой с автоматическим исправлением:
- Проверяет SSL сертификаты
- Применяет миграции с исправлением
- Сохраняет все данные

### `fix-migrations-now.sh`
Быстрое исправление на работающем сервере:
- Не останавливает сервисы
- Исправляет миграции в фоне
- Перезапускает только backend

## Использование

### Для нового деплоя

```bash
# Рекомендуемый способ
bash safe-deploy.sh
```

### Для исправления ошибок

```bash
# Если ошибка уже произошла
bash fix-migrations-now.sh
```

### Для диагностики

```bash
# Проверка статуса миграций
cd backend
npx prisma migrate status

# Проверка существующих таблиц
npx prisma db execute --stdin <<< "SELECT table_name FROM information_schema.tables WHERE table_schema = 'public' ORDER BY table_name;"
```

## Мониторинг

### Проверка логов

```bash
# Логи backend
docker compose -f docker-compose.prod.yml logs backend

# Логи миграций
docker compose -f docker-compose.prod.yml logs migrations
```

### Проверка статуса

```bash
# Статус контейнеров
docker compose -f docker-compose.prod.yml ps

# Статус миграций
cd backend && npx prisma migrate status
```

## Устранение неполадок

### Ошибка P3018

```bash
# Автоматическое исправление
bash fix-migrations-now.sh
```

### Таблица не существует

```bash
# Ручное создание таблицы
cd backend
bash scripts/auto-fix-migrations.sh
```

### Миграции не применяются

```bash
# Проверка и исправление
cd backend
npx prisma migrate status
bash scripts/auto-fix-migrations.sh
```

## Безопасность

### Гарантии

- ✅ Данные никогда не удаляются
- ✅ Существующие таблицы не пересоздаются
- ✅ Создаются только недостающие таблицы
- ✅ Все операции логируются

### Ограничения

- ⚠️ Создает только базовую структуру таблиц
- ⚠️ Не добавляет данные в таблицы
- ⚠️ Требует ручного добавления данных при необходимости

## Рекомендации

1. **Всегда используйте `safe-deploy.sh`** для новых деплоев
2. **Создавайте бэкапы** перед критическими операциями
3. **Мониторьте логи** после деплоя
4. **Тестируйте на dev-окружении** перед продакшеном

## Поддержка

При возникновении проблем:
1. Проверьте логи: `docker compose logs`
2. Запустите диагностику: `bash fix-migrations-now.sh`
3. Проверьте статус: `npx prisma migrate status`
4. При необходимости запустите полный деплой: `bash safe-deploy.sh`
